# IaaS Architecture

AWS가 물리 서버, 네트워크, 스토리지 전체를 관리하기 위해 자체적으로 운영하는 OS 계층이 있다. 이 위에서 가상화 (Hypervisor)를 돌려서 EC2 같은 Virtual Machine를 만들어서 우리에게 제공한다.

> Hypervisor - A special kind of software (or firmware) that lets one physical computer run multiple Virtual Machines at the same time.

우리가 설치하는 EC2 인스턴스 OS는 우리의 애플리케이션을 실행하기 위한 서버 OS입니다. 여기서 우리는 패키지 설치, 보안 업데이트, 서버 설정, 애플리에이션 배포 등을 합니다.

# PaaS Architecture

PaaS에서 우리가 코드만 올리면 AWS가 필요한 런타임, 인프라, 인스턴스, 네트워크까지 자동으로 구성하고 배포해준다. AWS의 PaaS는 내부적으로 컨테이너 기술을 사용해 애플리케이션을 실행한다.

IaaS 과 PaaS를 비교하면 IaaS에서 애플리케이션을 구성하는 각 컴포넌트가 모두 가상 머신에서 독립적으로 동작합니다. 이주 과정은 쉽지만 가상 머신의 성능을 완전히 활용하지 못하며 운영비가 비싸다.

> 이주 (migration) - 애플리케이션을 다른 환경으로 옮기는 작업. (예: 온프레미스 서버 -&gt; 클라우드, 하나의 클라우드 서비스 -&gt; 다른 클라우드 서비스)

왜 IaaS에서 이주가 쉬울까? \
우리가 사용하고 있는 OS를 그대로 복사해서 애플리케이션을 그대로 다른 서비스로 옮길 수 있다.

왜 PaaS는 이주가 어렵나요? \
PaaS는 운영체제, 런타임, 인프라 구조가 표준화된 플랫폼에 고정되어 있어요. 그래서 기존 애플리케이션을 그대로 옮기지 못하고 구조를 새로 조정하거나 refactoring 해야 할 때가 많다.

## 컨테이너가 뭐지?

**컨테이너는 애플리케이션을 실행하는 데 필요한 코드, 런타임, 라이브러리(의존성) 등을 하나로 묶은 실행 단위입니다.**

- **컨테이너 - 앱 실행에 필요한 모든 요소를 포함한 패키지 (운영체제 커널 제외)**
- 컨테이너는 어떤 환경에서도 동일하게 실행되므로, **서버 간 이동(이주)** 과 **배포**가 매우 편리합니다.
- 컨테이너는 독립된 OS를 포함하지 않고 **호스트 OS의 커널을 공유**하여 동작합니다.
- 하나의 가상머신(VM)에서도 **여러 개의 컨테이너가 동시에** 실행될 수 있습니다.

# Service Architectures

### 1. Monolithic Service Architecture

Monolithic Architecture는 애플리케이션을 구성하는 모든 컴포넌트가 하나의 코드베이스 안에서 통합되어 하나의 단일 애플리케이션으로 동작하는 구조를 말합니다. 이 구조는 개발 초기 단계에 만들 수 있지만 서비스 규모가 커질수록 유지보수와 확장성이 어려워집니다.

![](/images/w4_p1/1775644538375.png)\### 2. Microservices Architecture

Microservices Architecture는 애플리케이션을 여러 개의 작은 독립적인 서비스로 나누어 각각을 따로 개발·운영·배포하는 구조입니다.\
각 서비스는:

- 독립된 코드베이스

- 독립된 데이터베이스 또는 데이터 스키마

- 독립된 런타임

- 독립된 배포

- 독립된 스케일링을 가지고 있습니다.

## DevOps이 무언지

DevOps는 개발자(Dev)와 운영팀(Ops)이 협력하여 소프트웨어를 빠르고 안정적으로 개발, 배포, 운영하는 문화이자 방법론이다.

#### DevOps의 핵심은 개념들을 알고 있는 것이 좋아요

### 1. **CI (Continuous Integration) – 지속적 통합**

- 개발자가 코드를 push하면
- 자동으로 빌드 & 테스트 실행
- 코드 안정성 확보

도구: GitHub Actions, Jenkins, GitLab CI

---

### 2. **CD (Continuous Delivery / Deployment) – 지속적 배포**

- 테스트 통과 → 자동 배포
- 안정적인 자동화된 배포 파이프라인

도구: AWS CodeDeploy, ArgoCD, Spinnaker

---

### 3. **Infrastructure as Code (IaC)**

- 인프라(서버, 네트워크)를 코드로 관리
- 동일한 환경을 빠르게 생성 가능

도구: Terraform, CloudFormation

---

### 4. **Monitoring & Logging**

- 서비스 모니터링
- 문제 자동 감지

도구: Prometheus, Grafana, CloudWatch

---

### 5. **Automation (자동화)**

- 빌드, 테스트, 배포, 인프라 생성 모두 자동화

# **Conclusion**

지금까지 클라우드 인프라(IaaS / PaaS), 컨테이너, 서비스 아키텍처, 그리고 DevOps까지 전체 큰 그림을 훑어보았습니다. 이 개념들은 각각 따로 존재하는 것이 아니라, 하나의 흐름 속에서 연결되어 있어요.

- **IaaS → PaaS → Containers → Kubernetes**는\
  애플리케이션을 더 빠르고, 더 안정적이고, 더 확장 가능하게 만들기 위한 기술적 진화입니다.
- **Monolithic → Microservices**는\
  서비스 규모가 커질수록 유지보수가 어려워지는 문제를 해결하기 위한 아키텍처 진화입니다.
- **DevOps**는\
  이런 기술적 변화 위에서 팀이 더 효율적으로 협력하기 위한 문화적/실천적 접근 방식입니다.

즉, 개발자가 현대 서비스 환경에서 성장하려면 애플리케이션뿐 아니라 **인프라 → 배포 → 운영 → 아키텍처**까지 연결된 큰 흐름을 이해하는 것이 중요합니다.
