# Introduction

컴퓨터로 메시지를 보내거나 웹사이트를 열 때, 그 데이터가 어떤 과정을 거쳐 상대방에게 도착하는지 궁금해 본 적 있나요?\
오늘은 네트워크의 기초 개념과 OSI 7계층을 통해 **데이터가 실제로 이동하는 전체 흐름**을 간단하고 현실적으로 설명해보겠습니다.

# What is Network?

**컴퓨터 네트워크란 여러 기기(스마트폰, 컴퓨터, 서버 등)가 서로 정보를 주고받기 위해 연결된 구조**를 말합니다.\
이 연결 덕분에 우리는 **메시지를 보내고, 웹사이트에 접속하고, 게임을 하고, 파일을 공유**할 수 있죠.

그렇다면 내가 보낸 데이터는 정확히 어떤 단계를 거쳐 다른 사람에게 전달될까요?\
이 과정을 이해하려면 OSI 모델을 알면 됩니다..

### OSI 7 Layers

OSI(Open Systems Interconnection) 모델은 **컴퓨터 간 통신 과정을 7단계로 나눈 표준 구조**입니다.\
쉽게 말해,

> **“내가 보낸 메시지는 어떤 단계를 거쳐 상대방에게 도착하는가?”**\
> 를 체계적으로 설명한 로드맵이라고 보면 됩니다.

각 Layer를 실제 상황에 연결해서 쉽게 설명해볼게요.

![](/images/test/1775532561791.png)\- **Application Layer (L7)**\
Level 7(응용 계층)은 사용자가 생성한 데이터를 HTTPS, SMTP, FTP, DNS, DHCP 등의 프로토콜을 사용하여 전송 가능한 형식으로 포맷팅하는 역할을 한다. 또한 상황에 따라 어떤 프로토콜을 사용할지 결정하는 역할도 담당한다. 예를 들어 웹 요청이면 HTTPS, 이메일 전송이면 SMTP를 선택하는 방식이다.

- **Presentation Layer (L6)**\
  Level 6(표현 계층)은 응용 계층에서 받은 데이터를 상대방 시스템이 이해할 수 있는 형식으로 변환하는 역할을 한다. 주요 기능으로는 데이터 인코딩/디코딩, 암호화/복호화, 압축/해제가 있다. 예를 들어 데이터를 전송하기 전에 SSL/TLS로 암호화하거나, JPEG·MP4 같은 미디어 형식으로 변환하는 것이 표현 계층에서 처리된다.
- **Session Layer (L5)**\
  Level 5(세션 계층)는 두 기기 간의 연결(세션)을 시작, 유지, 종료하는 역할을 한다. 즉, 데이터를 주고받는 동안 연결이 끊기지 않도록 관리하며, 통신이 끝나면 세션을 정상적으로 종료한다. 예를 들어 로그인 후 웹사이트를 이용하는 동안 연결 상태가 유지되는 것이 세션 계층이 동작하는 대표적인 예시이다.
- **Transportation Layer (L4)**\
  Level 4(전송 계층)는 데이터를 송신측에서 수신측까지 신뢰성 있게 전달하는 역할을 한다. 데이터를 작은 단위(세그먼트)로 나누어 전송하고, 수신측에서 다시 조립한다. 주요 프로토콜로는 TCP와 UDP가 있으며, TCP는 데이터 손실 여부를 확인하며 정확하게 전달하고, UDP는 확인 없이 빠르게 전송한다. 예를 들어 파일 다운로드는 정확성이 중요하므로 TCP를, 실시간 영상통화는 속도가 중요하므로 UDP를 사용한다.
- **Network Layer (L3)**\
  Level 3(네트워크 계층)는 데이터를 출발지에서 목적지까지 최적의 경로를 찾아 전달하는 역할을 한다. IP 주소를 기반으로 데이터의 경로를 설정하며, 데이터를 패킷(Packet) 단위로 나누어 전송한다. 주요 프로토콜로는 IP, ICMP 등이 있으며, 라우터(Router)가 이 계층에서 동작하는 대표적인 장비이다. 예를 들어 한국에서 미국 서버로 데이터를 보낼 때, 네트워크 계층이 여러 라우터를 거쳐 최적의 경로를 선택한다.
- **Data Link Layer (L2)**\
  Level 2(데이터 링크 계층)는 같은 네트워크 내에서 기기 간 데이터를 신뢰성 있게 전송하는 역할을 한다. IP 주소 대신 MAC 주소를 사용하여 기기를 식별하며, 데이터를 프레임(Frame) 단위로 나누어 전송한다. 또한 전송 중 발생하는 오류를 감지하고 수정하는 기능도 담당한다. 주요 장비로는 스위치(Switch)와 브리지(Bridge)가 있으며, 이더넷(Ethernet)과 Wi-Fi가 대표적인 프로토콜이다.
- **Physical Layer (L1)**\
  Level 1(물리 계층)은 데이터를 실제 물리적인 매체를 통해 전기 신호, 광신호, 무선 신호 형태로 전송하는 역할을 한다. 0과 1로 이루어진 비트(Bit) 단위로 데이터를 처리하며, 케이블, 허브, 리피터 등의 물리적 장비가 이 계층에서 동작한다. 예를 들어 랜선(LAN Cable)을 통해 전기 신호로 데이터를 전달하거나, 광케이블을 통해 빛의 형태로 데이터를 전송하는 것이 물리 계층에 해당한다.

# IP 주소를 상세하게

IP 주소는 네트워크에 연결된 기기를 식별하기 위한 **논리적 주소**입니다. 집 주소가 없으면 택배를 받을 수 없듯이, IP 주소가 없으면 인터넷상의 어떤 서비스도 이용할 수 없습니다.

### 1) IPv4 (Internet Protocol version 4)

인터넷의 탄생과 함께 만들어진 가장 대중적인 주소 체계입니다.

- **구조:** `123.45.67.89`와 같이 4개의 마디로 구성됩니다.

- **기술적 특징:** 각 마디는 **8비트(0\~255**)로 이루어져 있어, 전체 주소는 **32비트** 입니다.

- **한계:** 생성 가능한 주소는 총 **2^32 (약 43억 개**)입니다. 전 세계 인구수와 기기 수를 고려하면 턱없이 부족한 양입니다.

---

### 2) IPv6 (Internet Protocol version 6)

IPv4의 주소 고갈 문제를 근본적으로 해결하기 위해 등장한 차세대 주소 체계입니다.

- **구조:** `2001:0db8:85a3:0000:0000:8a2e:0370:7334`와 같이 16진수 8마디로 구성됩니다.

- **기술적 특징:** 전체 **128비트**의 길이를 가져서 총 **$2^{128}$개**의 주소를 만들 수 있습니다. (지구상의 모든 모래알에 주소를 붙여도 남는 수준입니다.)

- **장점:** 주소 생성뿐만 아니라 보안성(IPsec 내장)과 데이터 처리 속도 면에서도 IPv4보다 우수하게 설계되었습니다.

---

### 3) 왜 아직도 IPv4를 많이 쓸까?

주소가 부족함에도 불구하고 IPv6로 완전히 갈아타지 못하는 이유는 크게 3가지입니다.

1. **NAT(Network Address Translation)의 활약:** 공유기가 '공인 IP' 하나를 여러 대의 기기(사설 IP)가 나눠 쓰게 해주는 기술 덕분에 IPv4의 수명이 획기적으로 늘어났습니다.

2. **호환성 문제:** IPv4와 IPv6는 서로 '언어'가 달라서 통신이 직접 되지 않습니다. 이를 위해 장비를 교체하거나 복잡한 변환 기술을 써야 하는데, 이 비용이 막대합니다.

3. **장비 지원의 한계:** 오래된 라우터나 구형 기기들은 IPv6를 인식하지 못하는 경우가 많아 전 세계적인 인프라 교체에 시간이 걸리고 있습니다.

## Private IP vs Public IP

IP 주소를 public 및 private이라고 2가지로 나눈다.

- **Public IP**는 인터넷에서 보이는 “집 주소”처럼, 외부에서 나의 네트워크를 구분하는 주소.
- **Private IP**는 집이나 학교 같은 내부 네트워크 안에서만 쓰는 “방 번호” 같은 주소라서, 인터넷 밖에서는 보이지 않는다.

이렇게 **Public IP와 Private IP로 나누는 이유는 크게 3가지**

- **IP 주소가 부족해서**\
  IPv4 주소는 개수가 한정돼 있어서, 모든 기기에 Public IP를 줄 수 없다.\
  → 그래서 내부에서는 Private IP를 쓰고, 외부와 연결할 때만 하나의 Public IP를 공유함(NAT).
- **보안 때문에**\
  Private IP는 외부 인터넷에서 직접 접근할 수 없어서,\
  네트워크 내부 기기들이 **더 안전하게 보호**된다.
- **관리하기 편하려고**\
  내부 네트워크는 관리자 마음대로 IP를 할당할 수 있어 여러 기기를 많이 쓰는 회사나 집에서 훨씬 **운영하기 쉬움**.

## 🔢 Subnet & Subnet Mask

## Subnet이란?

큰 네트워크를 **여러 개의 작은 네트워크로 나누는 것**\
예:\
학교 Wi-Fi → 강의실 / 도서관 / 연구실 네트워크

## Subnet Mask란?

IP 주소에서\
**“어디까지가 네트워크 부분인지”를 정하는 기준선**

예: `255.255.255.0 → /24`

- 앞 24bit → 네트워크
- 뒤 8bit → 호스트

## 왜 Subnet이 필요할까?

1. **네트워크 효율적 분리**
2. **IP 주소 절약**
3. **보안 강화 및 접근 제어 가능**
